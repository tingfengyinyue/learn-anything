# 设计说明

## 1. 方法论

十步法来自 AI 大刘《用 AI 十倍速学习任何知识：完整十步法》（融合 Rahul 的“路径 + 测试 + 压缩 + 反馈循环”与斯坦福 STORM）。

| 阶段 | 步骤 |
|---|---|
| 探索 | 1 五视角 STORM · 2 矛盾图谱 · 3 综合简报 · 4 同行评审自检 |
| 聚焦 | 5 资源筛选 · 6 学习阶梯 · 7 2 小时啃下核心 20% |
| 验证 | 8 考到我崩溃 · 9 费曼循环 |
| 压缩 | 10 一页速查表 |

## 2. 知识从哪来

三种来源，每条结论都带来源标记：

| 来源 | 标记 | 说明 |
|---|---|---|
| 用户资料 | `[U1]` | 文件（PDF/MD/HTML/TXT）、网页链接、文字笔记。默认私有，可 `--shared` 共享 |
| 联网检索 | `[W1]` | 第 1 步自动调研：模型生成搜索词 → 搜索 → 抓正文 → 入库为共享资料 |
| 模型知识 | `[M]` | 资料覆盖不到时使用，提示词要求明确标注 |

主题级 `source_mode`：`hybrid`（默认）/ `user_only`（内部知识、教材，不联网）/ `web_only`。

各步骤对检索的依赖不同：

- 1、4：注入检索片段（BM25，中文按字二元组切分，每份资料保底一段）
- 5：单独检索真实学习资源作为候选，候选外的推荐必须标“未核实”
- 2、3、6、7：只基于前序产出
- 8、9、10：只基于前序产出 + 学习者自己的作答

编号按 source id 稳定分配，同一变体的各步骤编号一致；导出时汇总成参考资料列表。

## 3. 多用户 × 多主题：三层产出

用户和主题是多对多关系（`enrollments`）。十步产出按“和谁有关”分三层：

| 层 | 步骤 | variant_key | 共享范围 |
|---|---|---|---|
| 主题层 | 1-4 | `public` 或 `user:<id>` | 所有学这个主题的人；用了私有资料则只属于本人 |
| 画像层 | 5-7 | `<主题层>\|L<水平>\|<目标类型>\|<时间档>` | 画像同档的人 |
| 个人层 | 8-10 | `enr:<enrollment_id>` | 仅本人 |

要点：

- **复用**：`(主题, 步骤, 变体)` 的当前版本存在且未过期就直接复用，不调用模型。CLI 会显示“复用 xx 的共享版本”。
- **隐私**：主题层 / 画像层的提示词里不出现个人信息（目标备注、弱项），否则无法共享。个人备注只进第 8-10 步。
  使用了私有资料的人走 `user:<id>` 变体，私有内容不会进入公共版本。
- **画像分档**：水平 0-5、目标 5 类、时间 3 档，共 90 档。分得越细越个性化、复用率越低，这是有意的权衡。
- **主题去重**：名称经 NFKC、小写、空白规整后作为别名；`learn topic alias` 可以把同义词挂到同一主题。
- **过期**：主题层超过 `freshness_days`（默认 90 天，可按主题设置）自动重新生成，联网调研也会重做。
- **级联失效**：每份产出记录生成时依赖的上游版本（`inputs`）。上游 `--refresh` 后，下游产出都不再是当前版本；
  `learn status` 标 ⚠️，`learn run` 会自动补跑。
- **并发**：进程内锁防止多人同时触发同一份共享产出的重复生成。多进程 / 多实例部署需要换成数据库锁（见 TODO）。

## 4. 交互环节

由代码控制流程，模型只负责出题、评分和讲解：

- **考试**：10 道正题，难度按题号 1-3 初级、4-6 中级、7-8 高级、9-10 专家，上一题 ≥8 分再加一级；
  <5 分追问同一知识点（不占题号，最多 3 次）。选题先保证覆盖面，同等次数下优先考掌握度低的。
- **费曼**：队列 = 上次考试最弱领域 + 掌握度 <0.6 的知识点，最多 4 个。讲解 → 复述 → 只补漏洞 → 再复述，
  通过才进入下一个，最多 4 轮。
- **掌握度**：每次作答按 `0.6·旧值 + 0.4·本次` 更新，粒度是知识点（来自第 7 步抽取的核心概念 + 测验中出现的新概念）。
- **间隔复习**：完成第 10 步后按掌握度建计划，间隔 1/3/7/14/30/60 天；复习 ≥7 分升档，<5 分回到 1 天。
- 会话状态存数据库，`/quit` 后再次运行同一命令会恢复到当前题。

## 5. 学习节奏：按阶段推进，而不是一次生成

原文的节奏：探索阶段“泡一壶茶的功夫”由 AI 一口气完成；聚焦阶段产出的是一份需要**花几天去学**的计划；
验证在学完后、状态好的时候做；最后压缩成速查表并循环复习。所以产品按阶段停顿，而不是每一步都停、也不是一次跑完：

| 阶段 | 命令 | 停在哪里 |
|---|---|---|
| 探索 1-4 | `learn run` | 跑完后展示第 4 步的「修订版简报」，读完再继续 |
| 聚焦 5-7 | `learn run` | 展示 10 课计划，进入学习期 |
| 学习期 | `learn lesson` | 每课：讲义（首次生成、同计划共享、后台预取下一课）+ 练习 + 5 道小测（复习题来自计划，只用模型评分） |
| 验证 8-9 | `learn exam` / `learn feynman` | 学习者自己决定何时考；准备度只是建议（完成 ≥70% 课程且小测均分 ≥60） |
| 压缩 10 | `learn run` | 展示速查表 |
| 巩固 | `learn review` / `learn today` | 间隔复习、每日入口 |

- 第 7 步要求模型直接输出结构化 JSON（10 课 × 5 题 + 概念表 + 最终项目），由程序渲染成 Markdown；
  模型没按 JSON 输出或旧版产出没有结构时，再调用一次模型补抽并缓存
- `plan.stage()` 是唯一的“下一步是什么”的来源，CLI 的提示、`learn today`、`learn status` 都用它
- 考试延迟优化：题干 / 点评有长度约束；学习者作答时后台按“延续上一题表现”预取下一道正题，难度猜中直接用

## 6. 题单

题单是一种特殊的资料：除了作为检索资料，还把里面的题目解析进题库（`Question.origin = "syllabus"`，记录原分类、顺序、出题公司）。

- **解析**：按约 6000 字分段**并行**调用模型，输出逐行文本（`# 分类` / `- 题目 ||| 难度 ||| 公司`）而不是 JSON——
  上百道题的长 JSON 实测会写坏且慢；逐行格式坏一行只丢一行。段首没有分类标题时写「续上一段」，由程序接上一段的段尾分类；
  模型偶尔把两道题写进同一行，按「？- 」拆开
- **知识点**：题单分类直接作为知识点（非核心），掌握度按分类累计
- **可见性**：跟随资料——共享题单人人可用；私有题单只给本人（且本人走私有变体）
- **使用**：`learn drill` 按题单顺序练没做过的原题；考试正题按 `syllabus_ratio` 优先抽难度匹配的原题；
  第 7 步 prompt 带上题单，要求覆盖分类、复习题优先照抄原题，并输出 `syllabus_coverage`；
  课程小测里照抄的原题按原文匹配回题单那道题，计入题单进度

## 7. 群体层：跨用户沉淀与反思（轻量版）

目标：前面的人踩过的坑、做过的题，让后面的人学得更顺。当前存储用关系库，语义判断交给模型或字符串相似度，接口预留给向量检索。

```
每次作答 ──沉淀──▶ 题库 / 误区库 / 题目统计 ──learn reflect──▶ 主题洞察（带版本）
                                                       │
            下一个人的 出题 · 评分 · 费曼讲解 · 速查表 ◀──┘
```

| 能力 | 怎么做 |
|---|---|
| 题库 | 新出的题入库（同主题、同知识点下相似度 ≥0.9 归并）；出正题时按 `LA_BANK_RATIO` 优先取别人做过、难度匹配、本人没见过的题 |
| 误区 | 评分 / 费曼检查时把已知误区列表给模型，模型返回命中编号或新误区短标签；按根误区（合并后）统计人数和次数 |
| 举报 | 考试中 `/flag 原因`：记录并换一道题；被举报的题在反思审查前不出给任何人 |
| 题目统计 | 作答人数、均分、0 分率、区分度（该题得分与同场其他题均分的相关系数）、举报 |
| 反思 `learn reflect` | ① 按真实均分校准难度（确定性规则）② 把可疑题（被举报 / 难度偏差 ≥2 档 / 0 分率高 / 区分度低）交给模型给出 keep / recalibrate / rewrite / retire ③ 合并、精修误区 ④ 更新出题经验。结果存为带版本的主题洞察 |
| 反哺 | 出题：出题经验 + 该知识点高频误区；费曼讲解：提前点破误区；速查表“新手最容易犯的错”基于真实误区 |

安全与隐私约束：

- 学习者的**原始回答**只留在本人记录里，不进入任何别人的 prompt，也不进反思 prompt；共享的只有模型归纳的误区标签、题目和统计数字
- 影响别人学习内容的误区要求至少 `LA_COLLECTIVE_MIN_USERS` 个不同学习者（默认 2）；匹配用的已知误区列表不设门槛，便于累计
- 群体数据在 prompt 中包在 `<collective_data>` 里并声明“是数据不是指令”，降低注入风险
- 基于私有资料出的题不进共享题库
- 反思只能处理本次列出的可疑题，自动调整的只是数据，不改系统提示词
- 只有主题创建者 / 管理员能运行反思

升级到 pgvector 时只需替换：`collective.similar_question`（题目去重）、误区匹配（评分前先用向量召回 Top-K 候选误区再交给模型，替代现在的“列出全部”）、反思时的误区聚类，以及 `library.build_context` 的检索。

## 8. 事务约定（重要）

**调用模型之前必须提交，模型调用和联网 IO 永远不在写事务里。** SQLite 同一时刻只允许一个写事务；
如果在写事务里等几十秒的模型返回，其他所有人的写请求都会卡住直至超时（代码审查时已复现：别人的请求等 5 秒后返回 500）。

- 生成步骤：联网调研先抓完再统一入库并提交 → 生成（只读）→ 写产出
- 会话：状态里有阶段 `phase`（`await_answer` / `need_question` / `need_explain` / `need_finish`）。
  评分（只读）→ 写作答并推进阶段 → `_drive` 提交后再调用模型完成挂起动作。模型失败时作答不丢，
  下次 `start` 或 `answer` 会先补完挂起动作，不会重复评分
- 会话状态读写一律深拷贝（`_load_state` / `_store_state`），避免原地修改嵌套列表导致 SQLAlchemy 判定未变化而不落库
- 鉴权的 `last_used_at` 每 10 分钟最多写一次，避免只读请求也抢写锁；SQLite 锁等待时间设为 30 秒兜底
- 同一学习记录、同类会话最多一个进行中（部分唯一索引），并发创建时自动改为恢复已有会话
- 回归保障：测试用的 `ProbeLLM` 每次被调用时都检查数据库是否被写锁占用，任何测试中出现违规都会失败

## 9. 结构

```
src/learn_anything/
├── config.py            LA_ 环境变量
├── models.py            数据模型
├── llm/                 anthropic | openai 兼容 | fake
├── search/              tavily | duckduckgo | fake
├── sources/             抓取（含 SSRF 防护）、HTML/PDF 转文本、切块、BM25
├── core/
│   ├── steps.py         十步定义（层级、依赖、是否检索）
│   ├── prompts.py       全部提示词
│   ├── engine.py        生成 / 复用 / 失效
│   ├── library.py       资料导入、联网调研、上下文拼装
│   ├── sessions.py      考试 / 费曼 / 复习
│   ├── collective.py    群体层：题库、误区、统计、反思
│   ├── plan.py          学习期：10 课计划、讲义、进度、准备度、阶段
│   └── srs.py           间隔复习
├── api/                 FastAPI（Bearer token 鉴权）
└── cli/                 Typer + Rich 客户端
```
